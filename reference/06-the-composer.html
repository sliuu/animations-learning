The Composer

Say what should happen in words, watch the CSS write itself, and then change one thing and see what that one thing did.

Companions: Reference 01 · Reference 02 · Reference 04 Updated 2026-09-06

This sheet has no argument in it. Pick an object, pick a moment, switch words on and off, and the code and the result keep up. The question it exists to answer is what does that change look like — when you tune a number yourself, when you take the fade out, when you put it back.

Two stages, on purpose

The upper stage is the composition one edit ago. The lower one is now. Every time you touch something, now becomes before, and you can see the pair run together. A change you can only remember is a change you can't judge.

How to drive it

  1. Button and Drawer are the objects. Switching object is a reset — a button's composition means nothing on a drawer — so it starts each one from its own default.
  2. The moments are the row underneath. Each holds its own set of words, and the code panel prints all of them at once — the receipt is for the whole object. The last moment in each row (Return, Close) takes no words: it is the way back, and the only thing it owns is its own duration and curve. That is why a drawer can open in 220ms and close in 120ms, and why the code shows exactly where the second number lives.
  3. The checkboxes add and remove words. Two words that fight over the same channel (lift and sink both want translate) can't both be on, and the picker says so instead of letting the second one win silently.
  4. The code is editable. The words are the coarse path; clicking a value in panel 2 and typing is the exact one. A value the CSS parser would drop is flagged rather than applied, so nothing fails quietly.
  5. Play it, Loop, 0.25×, Hold this. Hold this freezes the upper stage so you can make several edits against one fixed reference instead of only the last one.
  6. The scrub runs both stages against the same clock, not each against its own duration — otherwise a 120ms and a 400ms version would look identical at every position of the slider, which is the one difference the comparison exists to show.

What the readout says

Duration, how many properties are being animated, how many of the three moments are in use, and the most expensive tier anything on the page touches — compositor, paint, or layout, in the sense Lesson 0002 uses them. It reports. It has no opinion about what it reports; the numbers are there so a judgment is yours to make and not the page's.

What's in it so far

Two objects. The button, with the words that D004 and 0010 put on a control — lift, sink, grow, shrink, fade, darken, lighten, shadow, tint, ring. The drawer, with the words D002 uses for a surface that lives off screen — slide, fade in, scale up, dim, shadow. A drawer's rest state is off screen, so those words write two rules rather than one: where the panel waits and where it arrives. Its stage has a real switch — click Filters, the scrim, or Apply and the printed CSS runs for real, rather than the scrubbed copy of it.

The object list is meant to keep growing across the design track: the card, the deck, the drag, the scroll section, the hero. The parts list lives in one file (assets/compose-catalogue.js), so adding an object is adding data, not adding a page.

Nothing plays on load, and nothing loops unless you switch loop on. An edit does preview itself, because watching the change is the sheet — but if your system asks for reduced motion, that preview is dropped and only Play, Loop and the scrubber move anything, since pressing one of those is the request. Every comparison is still readable standing still. Nothing you do here is saved — reload to reset it.

Easing & Timing

The decision tables. Print this one.

Companion to Lesson 0001 Sources: Kowalski, Comeau, MDN

Gate 1 — Should this animate at all?

Frequency of use decides. The more often a user sees it, the shorter and subtler it must be — and past a threshold, absent.

How often the user sees itVerdict
100+ times/day — keyboard shortcuts, command palette, arrow-key navigationNo animation. Ever.
Tens of times/day — hover states, list selection, tab switchesRemove, or cut to 100–150ms
Occasional — modals, drawers, toasts, dropdownsStandard animation
Rare or once — onboarding, empty states, success moments, marketingRoom for delight
Hard rule

Never animate keyboard-initiated actions. They repeat hundreds of times a day, and animation makes them feel slow, delayed, and disconnected from the keypress. Raycast has no open/close animation — that is the correct call for something opened all day long.

Gate 2 — What is the purpose?

Every animation needs an answer. These are the legitimate ones:

PurposeLooks like
FeedbackButton scales to 0.97 on press — the interface confirms it heard you
OrientationDrawer slides up from the edge it lives on, so you know where it went
Spatial consistencyToast enters and exits the same direction, making swipe-to-dismiss obvious
State indicationA morphing button shows something changed
ExplanationMarketing animation demonstrating how a feature works
Preventing jarring changeContent appearing from nothing reads as broken; a transition reads as intended

“It looks cool” is not on this list. If that is the only answer and the user sees it often, cut it.

Gate 3 — Which curve?

Is the element entering or exiting?
├─ yes ─────────────────► ease-out
└─ no
   ├─ moving/morphing on screen? ──► ease-in-out
   ├─ hover or colour change? ─────► ease
   ├─ constant motion (marquee)? ──► linear
   └─ anything else ───────────────► ease-out
Never

ease-in on UI. It withholds movement during the exact window the user is watching most closely, so a 300ms ease-in feels slower than a 300ms ease-out at identical duration.

The curve library

The CSS keywords are too weak to feel intentional. Use custom curves. Paste this block into any project:

:root {
  /* Entrances, exits, anything responding to the user */
  --ease-out-strong:    cubic-bezier(0.23, 1, 0.32, 1);
  /* On-screen movement from A to B */
  --ease-in-out-strong: cubic-bezier(0.77, 0, 0.175, 1);
  /* Drawers and sheets — the iOS feel, via Ionic */
  --ease-drawer:        cubic-bezier(0.32, 0.72, 0, 1);
}

Reading a cubic-bezier

Four numbers: cubic-bezier(x1, y1, x2, y2) — two control points. X is time, Y is progress. Both curves always run from (0,0) to (1,1); only the handles differ.

  • First handle low and left (x1 small, y1 large) → leaps forward immediately. That is ease-out character.
  • First handle right along the bottom (x1 large, y1 = 0) → sits still, then rushes. That is ease-in. Avoid.
  • Y outside 0–1 → overshoot. y2 > 1 passes the target and comes back: a pop.
  • X outside 0–1 → invalid. The browser ignores the whole declaration.

Gate 4 — How long?

ElementDuration
Button press feedback100–160ms
Tooltips, small popovers125–200ms
Dropdowns, selects, menus150–250ms
Modals, drawers, sheets200–500ms
Marketing / explanatoryLonger is allowed
Ceiling

Product UI animations stay under 300ms. Above that the motion stops reading as responsiveness and starts reading as latency. Marketing pages are the exception — nobody is trying to get work done.

Stagger

30–80ms between items. Longer and the list feels like it is loading. Never block interaction while a stagger plays.

Asymmetry

Exit faster than enter. Entering, the user is being shown something; leaving, they have already decided and want it gone. A 300ms enter pairs with a 150–200ms exit.

Translating GSAP to CSS

Production sites — including the Claude for Chrome page — often use GSAP. Its ease names map onto standard curves, so you can read a site's source and reproduce it in CSS. GSAP's power scale is power1=Quad, power2=Cubic, power3=Quart, power4=Quint (GSAP docs); strength rises left to right: Sine < Quad < Cubic < Quart < Quint < Expo.

GSAPNamed curveApproximate CSS
power1.outeaseOutQuadcubic-bezier(0.25, 0.46, 0.45, 0.94)
power2.outeaseOutCubiccubic-bezier(0.215, 0.61, 0.355, 1)
power3.outeaseOutQuartcubic-bezier(0.165, 0.84, 0.44, 1)
power4.outeaseOutQuintcubic-bezier(0.23, 1, 0.32, 1)
expo.outeaseOutExpocubic-bezier(0.19, 1, 0.22, 1)
power1.inOuteaseInOutQuadcubic-bezier(0.455, 0.03, 0.515, 0.955)
nonelinearlinear

These are bezier approximations of polynomial curves — close enough that the difference is not perceptible, not mathematically identical. Values follow the Penner set catalogued at easings.net. Note that power4.out and --ease-out-strong are the same curve.

The quality rubric

Seven checks from “Great animations”. Run any animation past these:

#CheckFailing looks like
1Natural — obeys physics you already knowAppears from scale(0); constant velocity; no weight
2Fast — improves perceived performanceOver 300ms in product UI; user waits on the animation
3Purposeful — has a stated jobEverything moves; the eye has nowhere to rest
4Performant — holds 60fpsAnimating height, margin, top; visible jank
5Interruptible — redirects mid-flightKeyframes restarting from zero when re-triggered
6Accessible — honours reduced motionNo prefers-reduced-motion branch at all
7Coherent — matches the product's voiceBouncy springs in a banking dashboard

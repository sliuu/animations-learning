Lesson D014 · 25 minutes

Doing all of this in Framer

A primer for the tool the work actually gets built in: how Framer names the same ideas, where its model differs from the one this course teaches, and what it cannot express.

Skill: arrive in an unfamiliar tool already knowing which question to ask it ← Lesson D013

D013 ended on a set of named durations — a critique argued once, then reused by people who were not in the room. Open Framer and half that work is already done, by someone you will never meet, in numbers written down nowhere you can open. That is not a flaw. It is the most useful single fact about working in a tool of this shape: a canvas tool does not change what motion is, it changes the unit of the decision. In CSS the unit is a property, a duration and a curve. In Framer it is two states and a trigger, and the animation between them is worked out for you. Same drawer on the screen. A different question asked of you.

Say it out loud

An effect — a motion behaviour you attach to a layer from the Effects panel rather than write. Appear, Scroll Transform, Scroll Variant and Loop are the four.
A variant — a named alternative version of a layer. You draw the second one; the difference between the two is the animation.
A trigger — what moves a layer between variants: click, mouse enter, mouse leave, or a scroll position.
A transition — how the difference is crossed. Ease takes a duration and a curve; Spring takes stiffness, damping and mass, and has no duration at all.
Stagger — a transition property, not an effect, that walks a delay down a set of layers.
A code override — a small React function attached to a layer, and the door out of the canvas when the canvas has run out of triggers.

Below is the same drawer, authored twice. On the left it is three declarations. On the right it is two states and a trigger — how Framer says it, and how every tool of this shape says it. Open both, move it to a different edge, then press show me.

The unit of the decision

Two dashed rows on the left, five on the right. That asymmetry is the entire difference between the two models, and it is worth being precise about what it is not. It is not that the right-hand side is sloppy: it produced exactly the same motion, and it produced it from a description a designer can say out loud in a review. The tool has not removed decisions, it has moved the line between the ones you make and the ones it makes for you.

Notice which decisions ended up on which side. Moving the panel from the right edge to the bottom is a two-word change in both models, because that decision is genuinely design-level in both. But the duration crossed over. On the left you had to type a number before anything moved at all; on the right the drawer moved without ever asking, and something chose that number. Every animation has a duration, so if you did not choose one, the question is not whether a default exists but whether you have looked at it.

If you have read 0001: that lesson's argument for ease-out is an argument about a value you were typing. Here the same value arrives pre-typed, which is why the argument matters more rather than less — the tool's default is somebody's answer to that lesson, and you inherit it whether or not you ever read it.

The spring is the sharpest version of this. Ask for one on the right and you hand over stiffness, damping and mass, and you never hand over a duration, because a spring does not have one until it stops moving. The number in the panel is the result — the tool integrated the physics and told you how long that took. A spring is described by how it behaves, not by how long it lasts, and any tool that offers you both is offering you a duration you did not choose.

A default is a decision someone else made about your product

There is a version of this lesson that goes looking for things Framer cannot do, and it is a bad lesson, because the list is short, it is mostly wrong, and it expires. Framer can stagger a data-driven list. It can spring. It can scrub an animation against scroll position. Reaching for "the tool can't" is nearly always a sign that you have not yet found the control.

The durable question is the other one. In any tool that infers an animation, the review question is not "can it do this" but "which of these values did anyone actually choose". That question does not expire when the panel is redesigned, it can be answered by looking, and it is the one that catches real problems — because the failure mode of a good default is not that it looks wrong. It is that it looks fine, in five hundred places, none of which anyone ever examined.

Framer's defaults are good. That is precisely what makes them worth naming out loud: a bad default gets fixed the first time someone sees it, and a good one survives every review a product ever has. Write down which defaults you have adopted on purpose, and the ones you have not adopted become visible. This is the same artifact D013 called a token set. The only difference is that here you are naming decisions that already exist rather than inventing them, and that half of the work is easier, not harder.

If you have read 0009: the reduced-motion row in the panel is the one to check first in any new tool, for the reason that lesson gives — it is a correctness question wearing a preference question's clothes, and it is the row most likely to be filled in silently.

What the panel is called this week

Everything below is Framer's current vocabulary, and some of it will have moved by the time you read it. That is fine, and it is why the panel in the lab above is a stand-in for the model rather than a screenshot of the tool. Learn a tool's model rather than its menu, because the model changes on a scale of years and the menu changes on a scale of releases.

Motion in Framer arrives through the Effects panel, and the effects are sorted by trigger, not by feeling. Appear fires once when a layer arrives — when the page loads, or when the layer or its section comes into view. Scroll Transform is not triggered at all: it maps scroll position continuously onto position, scale, rotation or opacity, From one value To another. Scroll Variant flips a layer into a different state past a threshold. Loop repeats. Alongside them, variants plus a click or hover trigger cover everything a component does under a pointer, and Stagger rides on the transition of an Appear effect, which is how a list arrives one row at a time whether the rows are drawn by hand or come out of the CMS.

That sorting is the one structural thing to internalise, and it explains why two effects that look nearly identical on a page live in different places. An effects panel is organised by trigger rather than by feeling, so naming the trigger is how you find the control. The drill below is that, six times.

Where the canvas stops

The last specimen is the seam. A toast that appears when a save fails is not hard motion — it is a panel sliding up from an edge, which is the first thing anyone learns to build. What has no home on the canvas is the because. A canvas can see clicks, hovers, viewport positions and page loads, and a failed request is none of those.

That is the real shape of the boundary, and it is worth stating as a rule, because it predicts the cases you have not met yet. What runs out first in a design tool is triggers, not motion. Anything driven by something the page knows and the canvas does not — a request that failed, a value that crossed a threshold, a message that arrived, a list that reordered itself — needs a hand back to code, no matter how simple the movement is.

In Framer that hand-back is a code override, a small React function you attach to a layer, or a code component, which is a layer you wrote outright. Both give you the full Motion for React API — the library Framer itself is built on. This matters more than it sounds: the vocabulary does not change when you cross into code, only the spelling does. Variants stay variants. Transitions stay ease or spring, with the same three spring numbers. Stagger stays a property of a transition. You are not leaving the model you have been using; you are writing it down.

If you have read 0006: this is that lesson's tool-choice argument arriving from the other direction. There the question was when a library earns its bytes over plain CSS. Here it is when a canvas hands back to a library, and the answer has the same shape — you cross when the thing you need to express is not in the current vocabulary, not when the current vocabulary is merely inconvenient.

Three questions to ask any tool

Framer is one instance of a shape: a canvas that infers animations from states. Rive does it, Play does it, whatever ships next year will do it, and Figma's prototyping panel is a smaller version of the same idea. These three questions work on all of them, and they take about twenty minutes to answer in a tool you have never opened.

One: what is the unit of the decision here? Ask what the smallest thing is that you are asked to specify. If it is a property and a number, you are in the transition model. If it is a pair of states, you are in this one. Find the unit of the decision first, because every other question you have about a tool is downstream of it.

Two: what does it infer, and from what? Build one small thing and then hunt for every value you did not type — duration, curve, delay, what happens when the animation is interrupted halfway, what happens when the reader has motion turned off. Build the smallest possible thing in a new tool and then list what moved that you did not tell it to move. That list is the tool's opinion about your product, and it is twenty minutes to find and it lasts as long as you use the tool.

Three: where does it hand back to code? Every one of these tools has a seam, and the seam is where the triggers run out. Find it early, on purpose, while you are still choosing whether to build something here — a tool's escape hatch tells you more about its ceiling than its feature list does. A tool with a good hatch has a ceiling you can work under. A tool with no hatch has a ceiling you will discover in week three of a project.

What you have now

You can open Framer, or something like it, and be useful in it on the first afternoon — not because you know where the controls are, but because you know what the controls are for, which is the part that takes months to acquire by clicking. Every noun in the design track has a home in that panel, and the six specimens above were the drill for finding it.

The one habit worth carrying out of here: the first thing to do in a new tool is find out what it decided for you, not what it lets you decide. The second list is on the marketing page. The first one is the one that ships.
